# 已经付过代价的陷阱

*[English](TRAPS.md) · [Español](TRAPS.es.md)*

十六个各花掉一整个下午的问题。**它们全都是在使用中暴露出来的，没有一个是靠读代码
发现的，而且没有一个报错** —— 这正是把它们写下来的原因：这些恰恰是盯着代码找不到
的问题。

动到哪一部分之前，先读属于它的那一条。如果哪一条重新出现，那就是回归，比一个新发现
更值得重视。

---

## 在框架和它的路由里

1. **Cordis 连读取一个你没有在 `inject` 中声明的上下文属性都不允许。** 它不会返回
   空值：它会抛错。而在路由内部，这表现为**一个光秃秃的 400，一个字都没有**。
2. **末尾带斜杠的 `prefix` 路由什么都匹配不到。** 约定写的是「absolute pathname,
   no trailing slash」。带上斜杠就会落到兜底的 404，而那是一个**空的** 404 ——
   与「文件不存在」完全无法区分。
3. **如何区分这两者：** 看状态码**和大小**。0 字节的 404 来自框架；带 JSON 的来自
   插件。没有响应体的 400 是一个抛了错的路由。
4. **一个死掉的 socket 会带走整个框架。** 保持打开的连接在关闭时会发出 `error`，
   而没有监听者的 `error` 不会让请求失败：它会杀死进程，**日志里一行都没有**。
   四个地方都要监听：`req.close`、`req.error`、`res.close`、`res.error`。

## 在浏览器页面里

5. **后台标签页没有时钟。** Chrome 会把它的定时器限制到每秒一次，几分钟后限制到
   每**分钟**一次。任何依赖定时器的东西**恰好在需要它的时候停止工作** —— 也就是
   前面摆着另一个应用的时候。所以指令是从服务器**推送**下来的，走一条保持打开的
   路由：网络调用不是时钟，没有人会限制它。
6. **一个读取自身注册时那次渲染状态的处理器会吞掉指令。** 指令从外部到达，也就是说
   它落在一个可能此后没有重新渲染过的页面上。要在**指令到达的那一刻**读取状态。
   症状：生效一次，之后再也不会，而且悄无声息。
7. **发送时框架可能开启一个新会话。** 抱着之前的 id 不放，等于在等一个正被送到别处
   的回复。症状：屏幕上有答案，却说「智能体没有回答」。
8. **智能体的一个回合是好几个步骤。** 它思考、调用工具、查看结果、继续 —— 而每一步
   都是一个开始并**结束**的流。把第一次结束当成回合结束，就会在它正在回答时宣布它
   没有回答。而且每一步的文本都**从零开始**，所以新到的可能比之前的**更短**：比较
   长度会丢掉整整几个步骤。要比较文本。
9. **不要给智能体上时钟。** 出去查东西的那个，需要多久就是多久。等待不是故障，而一个
   为此变红的窗口只会教会你忽略颜色。

## 在浮动窗口里

10. **一个透明的置顶窗口在移动时会在屏幕上拖出残影。** 那不是两个窗口 —— 有人坚持
    说是，而那是错的：那是桌面没有重绘。解药是两个开关，而且两个都要在应用启动
    **之前**：
    `app.commandLine.appendSwitch('disable-features','CalculateNativeWinOcclusion')`
    和 `app.disableHardwareAcceleration()`。
    **收缩时同理**，而那是另一种情况：关闭菜单时窗口从 480 高变成 44，面板原本占据
    的区域会留在那里。这时两个开关够不着，因为什么都没有移动 —— 是**表面消失了**。
    把它隐藏再显示一次，强制重绘。
11. **不获取焦点的窗口无法拖动**，用 `-webkit-app-region: drag` 也不行：Windows
    根本不会把点击发给它。必须从主进程跟随指针。
12. **正在被拖动的窗口，只要你读它的尺寸，它就会变大。** 每秒读取并原样写回六十次，
    在非 100% 缩放的屏幕上，会累积一个只增不减的舍入误差：从 258×44 到 276×62 并
    继续上涨。`setPosition` 也没用 —— 实测过。尺寸由常量给定，绝不从窗口读回。
13. **第二个实例会抹掉第一个的设置。** 退出是异步的：抢锁失败的那个实例仍然会启动，
    在注册另一个已持有的快捷键时失败，然后把那次失败 —— 四个 null —— 写在好的设置
    上面。快捷键从此失灵，而且没有任何提示。抢锁失败的那个什么都不该碰。
14. **粗暴地杀死框架会留下孤儿窗口。** 浮动窗口是一个**独立进程**：框架正常关闭时会
    关掉它。不给它收尾就杀掉 —— 一个 `taskkill /F`、一个 `Stop-Process -Force` ——
    工具条就会独自活在屏幕上，没有人关闭它，也没有服务器可以对话。它不是卡死：它是
    孤儿。用它自己的叉号关掉。粗暴地重启几次框架，就会留下几条工具条。
15. **存下来的 null 会压过默认值。** 四个快捷键在窗口的设置文件里都是 `null`，启动时
    这些 null 战胜了 F8–F11：快捷键什么都不做，而且没有任何提示。在与出厂值合并之前，
    先过滤出真正被选择过的值。

## 关于话该怎么说

16. **「正在聆听」不能表示「麦克风是开着的」。** 那样写，屏幕就会不停地显示「正在
    聆听」，读到的人会理解为自己正被全程录音。它的意思是**此刻**有人在说话。回合
    之间，是静止。

## 另外三条关于测量的，适用于任何项目

- **一个重命名了标识符的测试视图什么也测不到。** CSS 不再作用于它，于是它给出了一个
  并不存在的设计的数字。要测量，就测量事物本来的样子。
- **用写错的模式去统计，比不统计更糟。** 九条字符串被当成已翻译，因为那个模式把文本
  里的任何一个逗号都读成了第三种译文。实际是零条。一个编造出来的数字会传播到所有用它
  做出的决定里。
- **配置文件会因为重写而损坏。** 重音符号变成了双重编码（「MicrÃ³fono」），麦克风的
  名字不再匹配任何设备，而应用完全没有报错：它只是选了默认设备。改动带重音符号的文件
  之后，要读回来检查。

## 关闭耳朵是对的，在那个位置关闭是错的

**检测器会听到它自己。** 在朗读回复时保持麦克风打开，轮次检测器会从扬声器里收到
插件自己的声音，判定有人在跟它说话，于是这东西就会永远自言自语。所以当时暂停了
检测器，这是正确的。

**但暂停的位置错了。** 它是在消息**发送**的那一刻暂停的 —— 而那一刻还没有任何声音
响起：智能体正在思考。也就是说，在一次可能持续好几秒的思考全程里，耳朵都是关着的，
而那期间根本没有任何回声需要防备。症状，在使用中发现：你在它思考时对它说话，它就是
听不见。界面上什么也不会显示，因为从内部看并没有出错。

正确的做法是在**第一个词真正发声时**关闭，而不是在消息发出时。

**下面还藏着另一条：从来没有请求过回声消除。** 麦克风是裸着打开的 ——
`getUserMedia({ audio: true })` —— 然后把决定权交给浏览器。而浏览器会根据你请求
设备的方式做出不同的决定。在一个语音插件里这不是细节：它决定了你能不能开着音箱说话。

**然后是，如何在不靠猜的前提下打断。** 固定的门槛是在拿别人的房间、音量和音箱下注。
赌高了它每隔两句就把自己切断，赌低了则永远打断不了。

所以不靠猜，靠测量。每次回复开始的前半秒，麦克风先听，而它听到的**就是**回声，
按定义如此：那时还没有人说话。那就是这台机器、这个房间、这个音量下的底线。要算作
人声，必须超过这个底线三倍并持续三分之一秒。每次回复都会重新测量，所以中途戴上耳机
会自动适应。

**还有两件事，没有它们这一切都白搭：** 让正在响的那句话停下并不等于安静下来 ——
如果不同时告诉朗读循环停止，它会在半秒后开始下一段。以及，检测器从听到回声的那一刻
起就在录音，所以如果不把那段缓冲丢掉，送去转写的内容**开头就是插件自己的声音**。

## 一条已经不再成立的

有好几个月，这里写着 **`dsh plugin remove` 会连带删掉配置文件里的链接**，还说必须手工
编辑 `package.json`。2026 年 9 月 1 日对照已安装命令自身的代码重新测量：如今它会
**根据已安装的内容来核对列表**，所以这条不再成立，README 写的是今天的事实。

它留在这里，是为了提醒另一件事：**陷阱也会过期**，在一件事不再发生之后还重复它，和
从来没写下它一样糟。

## 一条在 npm 下吓人、在 pnpm 下咬人的

**「某个包有未执行的安装脚本」在 npm 下是警告，在 pnpm 下是错误。** 那个脚本是
`msedge-tts` 的 `preinstall`，即 `npx only-allow pnpm`：它不构建任何东西，只是
强制**其自身**贡献者使用 pnpm 的一道闩，在别处会故意失败。跳过它不只是无害 ——
而是正确的。

在 npm 下事情到此为止：干净机器上实测，`npm install` 以 0 退出，该库列出 322 个
语音并返回真实音频，什么都没有构建，也没有安装任何一个本地语音。

**在 pnpm 下 —— 也就是框架配置文件所使用的 —— 同样的情况会让整条命令失败**，报
`[ERR_PNPM_IGNORED_BUILDS]`。而且 pnpm 不替你决定：它会把
`msedge-tts: set this to true or false` 写进配置文件的 `pnpm-workspace.yaml`
并留在那里。只要没人决定，该配置文件里的**每一次**安装都会失败 —— 包括别人的插件，
所以下一个撞上它的人根本没有理由怀疑到这个插件。把它设为 `false`。

这是在往一个已经装了本插件的配置文件里安装另一个毫不相干的插件时发现的。**在一个包
管理器里是警告，在下一个里就未必：同样的情况必须在人们真正会使用的那个里测量。**

## 一条我写下来却照样踩进去的

**读取 UTF-8 文件却不声明它是 UTF-8，会把它重新编码，而且没有任何东西会抗议。**
文件被一个默认使用系统代码页的工具读取、编辑，然后又以 UTF-8 写回。里面的中文变成了
双重编码 —— 原本是文字的地方变成一堵 `å…³äºŽ` 的墙。没有报错，没有失败的命令：它就
那样发布了出去，后来是因为一次搜索再也匹配不上它自己的标题才被发现。

关于配置文件因重写而损坏的那条陷阱，就写在上面三节的地方。写下来和读过它不是一回事。
**在改动任何带重音符号或非拉丁文字的文件之后，都要读回来检查** —— 而且如果这项检查
可以是一行代码而不是一双眼睛，那就让它是代码。
